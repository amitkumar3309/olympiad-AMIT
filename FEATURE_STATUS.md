# FEATURE_STATUS.md

Status values: `NOT_STARTED`, `IN_PROGRESS`, `IMPLEMENTED` (works end-to-end, verified by reading the actual data path — not just "a page exists"), `TESTED` (has automated test coverage), `DEPLOYED` (live in production).

A UI page existing with hardcoded/mock data is recorded as its own row/note — it does **not** count as `IMPLEMENTED` for the underlying feature.

**Infrastructure rows** (below the feature table) track the Milestone 1 backend foundation separately, since those are cross-cutting capabilities rather than user-facing features.

_Last updated: 2026-08-17, after the **complete security audit** — five confirmed findings, five fixes: CSRF closed by an origin check mounted for the whole API, `localhost:5173` dropped from the production CORS allow-list, the two public lookups no longer publishing a child's full legal name, security headers on the frontend deployment, and rate limits on the payment and credential-issuing admin routes. **Nothing was run**: that session could not execute `npm test`, `typecheck`, `lint`, `build` or `npm audit`, so every status below that depends on a green suite describes the state at the end of Milestone 19 — see the warning in [`PROJECT_STATE.md`](PROJECT_STATE.md) "Current Milestone". Before that, **Milestone 19 (payments, and the entry fee that gates the platform)** — Razorpay Standard Checkout verified server-side, a ₹100 entry fee that buys a seat in **the official Olympiad only** (it gated practice, mock tests and the daily challenge for one day on 2026-08-16 and the owner reversed that the next day — preparation is free), an entitlement **derived from a captured payment rather than stored as a flag**, one `requireEntry` gate answering 402 on `POST /exams/:id/attempt`, reconciliation in place of a webhook, and an admin console for the money and the fee. The fake QR "I've Paid" step in registration is **deleted**. This was the last planned development milestone. Before that, **Milestone 18 (generated questions need a human before they exist)** — generation now saves **nothing** until an examiner approves it, the blank-template generator is deleted, the full parameter set (chapters, Bloom's, language, marks, option count, instructions) reaches the prompt, a fifth question type `fill_blank` is auto-graded against author-listed answers, near-duplicates are refused, and a `GenerationLog` records every run. Short answer was deliberately **not** added — see the ADR. Before that, **Milestone 17 (AI question drafting)** — the admin question generator can now be backed by Google Gemini, behind the same kind of seam Milestone 16 used. It is **the only AI integration in the product**, it sends **no student data**, and it is optional: with no `GEMINI_API_KEY` the button creates blank drafts exactly as before. A model's output is never trusted — the taxonomy comes from the request, every candidate passes the same schema and LaTeX safety checks a hand-authored question passes, failures are reported rather than repaired, and everything written is a draft. Before that, **Milestone 16 (intelligent performance recommendations)** — five kinds of recommendation (weak topics, strong topics, difficulty, practice, insights) derived from the Milestone 15 pipeline and the published question bank, behind a **swappable engine seam** an ML or LLM implementation can be registered into. The default engine is statistical and is **deliberately not called AI**: findings are asserted on a 95% Wilson interval rather than a raw percentage, every recommendation carries the counts it was derived from as a required field, and nothing may suggest a topic the class bank cannot serve. **No AI provider is integrated** — Gemini was evaluated and declined for now on cost and children's-privacy grounds; see the three Milestone 16 ADRs. Before that, **Milestone 15 (performance analytics)** — every one of the eight requested student figures (accuracy, topic, subject and difficulty performance, time and progress trends, weak and strong areas) derived from real submitted attempts, plus admin question- and paper-performance. The never-written `StudentAnalytics` model was **deleted** rather than filled in. Before that, **Milestone 14 (the notification system)** — an audit first, because Milestone 12 had already built the in-app half, which was left alone. What Milestone 14 added is delivery and automation: a new `EmailOutbox` so **no user-facing request ever waits on SMTP** (registration used to await the handshake inline and lose the verification link on failure, with no record and no retry), six **system-generated** notifications for real events, per-student notification **preferences** for the two optional email streams — with security and transactional mail deliberately not switchable — an opt-in capped email broadcast for staff announcements, and an admin console that makes a failed delivery visible with the provider's own error text. Before that, **Milestone 13 (the official exam and the certificate system)** — the thing the product is named after, and previously its biggest gap. A new `Exam` collection with a mandatory announced window; a rewritten `ExamAttempt` with one attempt per student enforced by a unique index and a clock the server owns; a rewritten `Result` released as a deliberate administrative act that ranks the cohort and mints certificates in one operation; and a `Certificate` that can **only** come from that release, with every printable field snapshotted, a server-rendered `pdf-lib` PDF, and public verification keyed on a random code rather than the readable serial. Before that, **Milestone 12 (Complete Admin Platform)** — twelve of fourteen areas, with eight pre-existing ones deliberately not rebuilt: an event gallery, in-app notifications, platform analytics where every figure is counted from a collection, an unmasked admin leaderboard, and a badges overview. Before that, **Milestone 11 (Account administration and a real super-admin account)** — the bootstrap super admin became a `Student` document with a rotating refresh token and a revocable `tokenVersion`, and staff gained password reset, forced sign-out, a `blocked` status and super-admin-only delete. Before that, **Milestone 10 (Leaderboards and Hall of Fame)** — one ranking service every standing goes through, boards scoped by class and by period, equal XP sharing a rank, pagination whose ranks survive a page boundary, and a depth cap that keeps the public board from being walked._

_**No endpoint or page returns placeholder data anywhere in the product.** That was achieved in the Milestone 5 follow-up and has held since. Milestone 13 went further and emptied the "honestly empty" category too: the result portal, the dashboard's exam panel and the certificate page were all written as live queries against then-empty collections precisely so they would start working when submission landed, and they did. **Milestone 15 closed the category entirely**: `StudentAnalytics` was the last model the product read and nothing wrote, and it was **deleted** rather than filled in — analytics are derived on read from the four attempt collections. Every remaining model is both read and written._
